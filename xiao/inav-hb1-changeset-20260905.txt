# ---------------------------------------------------------------------------
# 1. rc_expo 20 -> 0   ⭐ the largest measured sim<->real divergence
# ---------------------------------------------------------------------------
# fc_core.c:397 picks the expo BY FLIGHT MODE: manual_rc_expo (0) under MANUAL,
# stabilized rc_expo (20) under ACRO. Moving the NN from MANUAL to ACRO in 043
# therefore made the action space NON-LINEAR without anyone changing a knob.
#
# Confirmed from the 2026-09-05 blackbox by fitting rcData -> rcCommand:
#   ACRO   n=3051 -> best fit expo=20 (residual 4.4 roll / 2.8 pitch counts)
#   MANUAL n= 969 -> best fit expo=0  (residual 0.6 / 0.9)
#
# Effect: every command short of FULL deflection is attenuated to 80-88% of
# linear. Full stick is unaffected -- which is why the T056 bench arm-C check
# (full pitch => ~100% elevator) passed and hid this.
#
# The sim models commandScale x maxRate, i.e. LINEAR. Setting rc_expo = 0 moves
# the AIRCRAFT onto the action space the genome actually trained against,
# instead of teaching the sim a knob that exists only for human thumbs.
#
# INAV default is 70; profile 1 was already lowered to 20. Range is [0,100].
# ⓘ Leaves MANUAL feel untouched -- that is governed by manual_rc_expo, = 0.

control_profile 1
set rc_expo = 0

# rc_yaw_expo stays at 30: yaw is provably unused on this airframe
# (axisRate[2] = axisF[2] = 0.0 across all 1044 engaged bench samples and all
# four flight spans). Changing it would be noise in the diff.

# ---------------------------------------------------------------------------
# 2. setpoint_kalman_enabled ON -> OFF
# ---------------------------------------------------------------------------
# ⚠️ MISNAMED: it is not a setpoint filter. gyro.c:506-510 applies
# gyroKalmanUpdate() to gyroADCf, and that value becomes gyro.gyroADCf[axis] --
# which is BOTH what the PID rate loop reads as its measurement AND what
# MSP2_AUTOC_STATE ships to the xiao as the NN's gyro input.
#
# So it sits in the control loop and in the policy's observation, as an
# input-adaptive IIR with STATE-DEPENDENT (non-constant) group delay, on top of
# the 25 Hz PT1 and the dynamic notch. The sim models neither it nor the notch.
#
# docs/inav-signal-path-audit.md:18 already concluded "almost certainly
# misconfigured ... NOT required for flight" -- and it was never acted on.
#
# ⓘ INAV default is ON. This is a deliberate deviation: an adaptive filter with
#    variable delay is the wrong thing to put in front of a policy that trained
#    on an instantaneous gyro.

set setpoint_kalman_enabled = OFF

save
